# MahoOS V1 architecture ownership map

Status: freeze candidate, audited 2026-09-25. This document describes the one intended owner for each state. It does not claim that every installer-era owner is implemented or certified.

## How to read the matrix

Every row answers the twelve ownership questions in the campaign:

- **State / source**: the state and its durable source of truth.
- **Observe**: the component that reads it.
- **Own / mutate / authority**: the single mutation owner, allowed writer, and exact authority.
- **Proof / verify**: durable mutation evidence and independent success postcondition.
- **Interruption / recovery**: behavior when the owner dies before or after mutation, and the recovery owner.
- **Freshness / missing**: what makes evidence stale and the fail-closed result when missing.
- **Finding**: unresolved conflict, missing owner, or other architectural flag.

`UNKNOWN` never means healthy. A process being root is not authority.

## Audit findings

No cyclic authority was found in the current update/generation model. Guardian remains an evidence and response authority, not a source of runtime, boot, or generation trust. The confirmed blockers are:

1. The installer and first-boot owners are specified but not implemented or certified.
2. Persistence baseline transitions do not yet consume exact healthy package-transaction authority, leaving a legitimate package change as an active L1.
3. Firewall boot-bound root receipt publication is implemented; physical activation and provider-coexistence certification remain pending.
4. Physical Signed Boot, fallback/recovery, storage-pressure/GC, and destructive final-source matrices remain uncertified.
5. The Vesktop package moved from `/usr/lib/vesktop` to `/opt/vesktop`; the confirmed local fix exists only as an unrelated dirty-worktree edit and must land through its own clean review path.
